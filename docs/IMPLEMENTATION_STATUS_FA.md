# وضعیت پیاده‌سازی CRM فارسی

این سند وضعیت واقعی شاخه `feature/crm-foundation` را ثبت می‌کند. وجود یک تصمیم یا سند نیازمندی به معنی پیاده‌سازی یا تأیید عملیاتی آن قابلیت نیست.

## وضعیت فعلی

### پیاده‌سازی‌شده در این شاخه
- سند نیازمندی نسخه اول CRM فارسی: `docs/REQUIREMENTS_V1_FA.md`.
- تصمیم معماری واحد پول تک‌ارزی تومان: `docs/adr/0001-single-currency-toman.md`.
- نوع دامنه‌ای `models.TomanAmount` با بازه صحیح نامنفی، JSON integer، SQL Scanner/Valuer و نوع صریح BIGINT برای GORM.
- تست‌های واحد برای قرارداد JSON، اعتبارسنجی بازه و رفت‌وبرگشت SQL نوع مبلغ.
- محاسبه دامنه‌ای مبلغ ردیف بر پایه تعداد هزارم، تخفیف و مالیات basis point با محاسبات صحیح و گردکردن half-up.
- تست‌های پایه برای جمع ردیف، گردکردن و ورودی‌های نامعتبر/سرریز.

### هنوز پیاده‌سازی نشده
- اتصال `TomanAmount` به مدل‌های Deal، Product، Quote و QuoteLine.
- حذف کامل `*_cents`، فیلدهای `currency` و تنظیم `deals.default_currency` از سرویس‌ها، Handlerها، Repositoryها، فیلترها و قرارداد API.
- Migration عملیاتی و گزارش ممیزی داده‌های قبلی؛ هیچ داده قدیمی به تومان تبدیل نشده است.
- اصلاح تجمیع قیف فروش، داشبورد، گزارش‌ها، PDF و ایمیل برای تومان.
- ماژول فاکتور، تبدیل پیش‌فاکتور پذیرفته‌شده به فاکتور، پرداخت جزئی/کامل، مانده و سررسید.
- ثبت بهای تمام‌شده و محاسبه سود بر اساس داده واقعی هزینه.
- Timeline کامل مشتری، ثبت تماس و اقدام بعدی، تشخیص مشتری بدون پیگیری و زمان‌بندی یادآورها.
- بومی‌سازی کامل فارسی، RTL، تقویم شمسی، فونت و قالب‌بندی مبلغ در تمام صفحات.
- آزمون یکپارچه، E2E، مهاجرت و بازیابی Backup در محیط اجرا.

## ترتیب اجرای لازم

1. **ممیزی قراردادها و وابستگی‌ها:** تهیه فهرست کامل استفاده از مبالغ، ارز، فیلترها، DTOها، OpenAPI، ایمیل، PDF و گزارش‌ها.
2. **لایه مالی:** اتصال نوع تومان به مدل‌ها و محاسبات؛ حذف مسیر چندارزی از قراردادهای فعال؛ افزودن تست مرزی، گردکردن، سرریز و تجمیع.
3. **مهاجرت داده:** ایجاد گزارش فقط‌خواندنی از تعداد و وضعیت رکوردها و کدهای ارز؛ افزودن ستون‌های جدید به‌شکل سازگار؛ توقف و نیاز به تصمیم مالک داده برای رکوردهای قدیمی. تبدیل خودکار cents به تومان ممنوع است.
4. **گردش‌کار اسناد:** فاکتور، اقلام، مالیات، شماره‌گذاری، ثبت پرداخت، مانده، ابطال و Audit Trail با محاسبه سمت سرور.
5. **CRM و پیگیری:** Timeline، تماس‌ها، وظایف، یادآورها و شناسایی مشتریان بدون پیگیری.
6. **رابط فارسی:** RTL سراسری، تقویم شمسی، اعداد و مبالغ فارسی، ترجمه تمام وضعیت‌ها و پیام‌ها و آزمون واکنش‌گرایی.
7. **تحویل و عملیات:** Docker، Nginx، پیکربندی امن، Migration/Backup/Restore، CI و تست‌های E2E.

## دروازه‌های پذیرش

- هیچ قرارداد مالی فعال، مبلغ را با واحد مبهم یا ارز قابل انتخاب دریافت/ارسال نکند.
- تمام محاسبات پولی فقط integer و در Backend انجام شوند.
- جمع سند، تخفیف، مالیات، پرداخت و مانده با تست مرزی و سرریز پوشش داده شوند.
- داده قدیمی بدون تصمیم مکتوب و تبدیل موردی/تأییدشده تغییر معنا ندهد.
- هیچ صفحه یا سند قابل مشاهده برای کاربر نهایی از نظر RTL، زبان یا تاریخ ناقص نباشد.
- CI، تست‌های Go، تست‌های UI و E2E روی نسخه نهایی موفق باشند.
- راهنمای نصب، ارتقا، بازگشت، Backup و Restore با اجرای واقعی تأیید شود.

## محدودیت تأیید

تغییرات ثبت‌شده در GitHub به‌تنهایی اثبات اجرای تست نیستند. تا زمانی که CI یا محیط محلی واقعاً اجرا و نتیجه آن بررسی نشده باشد، وضعیت تست «اجرا نشده/تأییدنشده» است.
