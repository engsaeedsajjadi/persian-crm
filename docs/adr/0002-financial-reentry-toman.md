# ADR 0002 — ثبت مجدد اطلاعات مالی با واحد تومان

- وضعیت: پذیرفته‌شده برای طراحی
- تاریخ: ۱۴۰۵/۰۹/۰۶
- تصمیم‌گیر: مالک محصول

## زمینه

مدل مالی فعلی CRM بر پایه مبالغ integer در ستون‌های `*_cents` و کد ارز ISO است. داده‌های موجود ممکن است با EUR یا ارزهای دیگر ثبت شده باشند. این مقادیر بدون نرخ تبدیل و تأیید مالک داده، معادل مبلغ تومانی نیستند.

## تصمیم

1. نسخه جدید مالی فقط با تومان کار می‌کند؛ هر مبلغ در API و مدل دامنه باید نام صریح `*_toman` داشته باشد و integer باشد.
2. داده‌های مالی قدیمی به تومان تبدیل یا با برچسب تومان نمایش داده نمی‌شوند.
3. ثبت مجدد به معنای ورود دوباره مبلغ معتبر برای هر Deal، Product، Quote و QuoteLine است؛ مقدار قدیمی صرفاً منبع بازبینی است و نباید خودکار به مقدار جدید کپی شود.
4. برای رکوردی که مبلغ تومان آن هنوز ثبت نشده، مقدار مالی باید «نیازمند ثبت مجدد» باشد و در محاسبه قیف فروش، درآمد، جمع پیش‌فاکتور و گزارش مالی وارد نشود.
5. ستون‌های legacy و تاریخچه قدیمی تا پایان تطبیق و تأیید مالک داده حذف نمی‌شوند. این داده‌ها فقط برای ممیزی/بازبینی نگهداری می‌شوند و قرارداد فعال API نباید آن‌ها را به‌عنوان تومان عرضه کند.
6. همه محاسبات مالی در Backend و با integer arithmetic انجام می‌شوند؛ استفاده از float برای پول ممنوع است.
7. مهاجرت باید افزایشی و قابل rollback طراحی شود؛ ابتدا ستون‌های جدید nullable و شاخص وضعیت ثبت مجدد اضافه می‌شوند. پاک‌سازی یا حذف legacy در Migration این مرحله مجاز نیست.

## جریان ثبت مجدد

- محصول: ورود قیمت واحد تومان و تأیید کاربر مجاز.
- معامله: ورود مبلغ معامله به تومان و تأیید کاربر مجاز.
- پیش‌فاکتور: ورود مجدد قیمت هر ردیف، سپس محاسبه سرورمحور subtotal، discount، tax و gross total به تومان.
- پیش‌فاکتورهای دارای ردیف قدیمی تا زمان ثبت مجدد همه ردیف‌ها از محاسبه و ارسال مالی جدید خارج می‌مانند.
- در هر تغییر، actor، زمان، مقدار قبلیِ legacy به‌عنوان مرجع ممیزی و مقدار جدید تومان در Audit Trail ثبت می‌شوند.

## دروازه‌های ایمنی

- پیش از اعمال Migration روی محیط واقعی، Backup کامل و آزمون Restore موفق الزامی است.
- گزارش پیش‌مهاجرت باید تعداد رکوردهای مالی، ارزهای legacy و ردیف‌های فاقد ارتباط را نشان دهد.
- هیچ نرخ تبدیل یا ضریب ثابت نباید در کد یا Migration وجود داشته باشد.
- تا زمانی که API، Handler، Service، Repository، گزارش‌ها، PDF، ایمیل و UI همگی از قرارداد تومان استفاده نکنند، قابلیت مالی تومان آماده انتشار نیست.
- Migration مرحله اول نباید داده legacy را پاک یا تغییر معنا دهد.

## وضعیت اجرا

این ADR تصمیم انتخاب‌شده را ثبت می‌کند؛ به‌تنهایی به معنی پیاده‌سازی مسیرهای API، Migration یا UI ثبت مجدد نیست. اجرای فنی باید با مدل‌ها، سرویس‌ها، Handlerها، Repositoryها، گزارش‌ها و آزمون‌های یکپارچه هماهنگ شود.
